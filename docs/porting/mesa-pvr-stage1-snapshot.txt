# Derived 1.13 CMD3D fields (FACT by differential capture):
#   0x14 = clear colour, RGBA8888 little-endian u32 (red=ff0000ff)
#   0x78 = (2*w - 4) | 0x02000000
#   0x80 = w-1,  0x84 = h-1
#   0xf8 = tpu_border_colour_table: low32 = GPU address, high32 = 0x20 (size)
#          (the low address happens to be 0x5400 + w*h for these goldens)
#   0x40 = event_pixel_pds_data (u64, low32 = GPU address)
#   0x48 = isp_scissor_base (u64: low32 address, high32 size 0x80)
#   0x50 = isp_dbias_base   (u64: low32 address, high32 size 0x80)
#   0x100 = pds_bgnd[0..2]      (24 B, PDS_BGRND0/1/2)
#   0x118 = pds_pr_bgnd[0..2]   (24 B, partial-render copy)
#   0x130 = flags, zls_stride, sls_stride, execute_count
#
# CORRECTION (2026-11-25): the earlier note that 0x40/0x48/0x50 were
# "render-target/PBE addresses" and that 0x100..0x12c was "static PBE state"
# was wrong.  The 0x100 block decodes exactly as PDS_BGRND0_BASE /
# PDS_BGRND1_BASE / PDS_BGRND3_SIZEINFO, and 0x40 is the pixel-event PDS
# data pointer.  Writing 0 at 0x40 makes the 1.13 3D firmware lock up
# (HWR EventStatus=0x10, ISP_END_MACROTILE) because the EOT program never
# runs.
